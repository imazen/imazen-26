set (`~/tmp/cm-fixtures-r13-3` — fixture bytes unchanged): the tie rule
certifies only when the tied pair lands within the calibrated T *and*
contains a correct-labelled hypothesis (far-out equidistant ties —
zen's 248–255 DNG renders, gm-best's orient6 double-rotations — are
`other` again, not `not-measurable`); `mis-tagged` fires only when the
raw pixels land on a managed hypothesis *and* the tag names the

the 48 webkit/opencv JXL cells per synthetic image are measured: WebKit
26.6 decodes all 16 JXL fixtures (`ok`, orientation correct,
`jxl-icc-p3` `p3-as-p3`) in both images; in-image Chromium declares JXL
unsupported (host Chrome 155 on Windows decodes it; Edge does not);
opencv 4.6 errors, 5.0 decodes.

Calibration is now pooled per fixture set: `CM_CALIBRATE_POOL` names
the sibling runs (identical `decoders` column → byte-identical
artifacts across siblings and their fixtures dir, --check-enforced);
`CM_CALIBRATE_EXTRA` is the strict `<dir>=<adapter>,...` syntax —
extras feed only the corpus bucket (synthetic fold: imageio×3+wic×3,
worst 23.00 → T=24; reps fold: imageio-raw+sips → T=4; Quick Look,
NSImage and sips-srgb are never folded). The corpus bucket scores only
signal-free fixtures, raw pixels, distance-to-`correct` — `.unm` HEIC
rows (drop-transform + unmanaged remux decoded by the run's own HEIC
readers against the libde265 `stored` base) are implemented and folded.
platform.txt is parsed as an append log — partial re-sweeps merge into
the platform record per key — and `--check` names every
expected-but-missing cell (lts ffmpeg `jxl-exif-orient6`/`jxl-jhgm`
crash cells).
